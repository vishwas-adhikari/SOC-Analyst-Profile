## Alert Overview
- **Severity:** High
- **Detection Source:** EDR / PowerShell Script Block Logging (Event ID 4104)
- **Asset Affected:** Gabriela (172.16.17.63 - Windows 10)
- **Threat Type:** Spearphishing / System Discovery / Exfiltration Over Web Service (Pastebin)
- **Verdict:** True Positive (Compromised / Exfiltrated)
- **Containment Status:** Contained (Isolated)

## 🧠 Attack Context / Technical Background
This incident represents a targeted post-exploitation data gathering and exfiltration campaign leveraging legitimate developer platforms. 

**The Mechanics:** After achieving initial access via spearphishing, the threat actor executes a custom PowerShell script (`system_users.ps1`). The script performs local system discovery by executing `whoami.exe /all` and writing the resulting user and group privileges to a temporary text file (`sys_usrs.txt`). For exfiltration, rather than utilizing a custom or suspicious C2 server that might trigger perimeter firewall rules, the script programmatically interacts with the **Pastebin API** (`https://pastebin.com/api/api_post.php`) using an embedded API key. It uploads the harvested system information as a public or unlisted paste and captures the resulting URL (`https://pastebin.com/rM7uP09b`), effectively exfiltrating internal data over a trusted HTTPS web service.

## Investigation Steps

### 1. Initial Access Verification (Phishing Triage)
The investigation began by reviewing the email delivery gateway to identify the initial intrusion vector.
- **Sender:** `help@dachfix.com` (Sent to `gabriela@letsdefend.io`).
- **Subject:** `Download and Apply the Critical Fix for Device Issues`
- **Lure:** The email instructed the user to download a critical system fix.
- **Payload URL:** EDR Browser History confirmed the user downloaded the archive via an AWS S3 bucket: `https://files-ld.s3.us-east-2.amazonaws.com/quick-fix.zip`.

### 2. Execution & PowerShell Script Analysis
Process telemetry and terminal history confirmed the user extracted the archive and executed the dropped script.
- **Process Lineage:** `explorer.exe` spawned `powershell.exe` with an execution policy bypass:
  `powershell.exe -ExecutionPolicy Bypass -File .\system_users.ps1`
- **Source Code Review:** Inspecting the contents of `system_users.ps1` revealed the attacker's exact operational logic:
  1. Executes `whoami.exe /all` and dumps output to `%userProfile%\sys usrs.txt`.
  2. Reads the content of `sys_usrs.txt`.
  3. Formats an API payload (`api_dev_key`, `api_option=paste`, `api_paste_code=$content`).
  4. Invokes `Invoke-RestMethod` against `https://pastebin.com/api/api_post.php`.
  5. Saves the returned Pastebin link to `%userProfile%\paste.txt`.

### 3. Exfiltration Verification (Pastebin Artifacts)
Live VM triage and log correlation confirmed the exfiltration completed successfully.
- **Staged File (`sys_usrs.txt`):** Inspected the local text file, which contained sensitive SID and user group membership details for the compromised asset.
- **Result File (`paste.txt`):** Captured the exact exfiltration artifact containing the live Pastebin URL generated by the script: `https://pastebin.com/rM7uP09b`.

## Analysis & Findings
The incident is a confirmed **True Positive**. The user "Gabriela" fell victim to a spearphishing email disguised as a critical system fix. The downloaded PowerShell script (`system_users.ps1`) executed successfully, harvesting user privileges via `whoami.exe /all`. The script then abused the legitimate Pastebin API to successfully exfiltrate this privileged account data to an external URL (`https://pastebin.com/rM7uP09b`). The host is fully compromised, and data leakage has occurred.

## 🛠️ Detection Engineering & Hunting Logic
To improve automated detection of Pastebin API data exfiltration, the following Sigma rule has been engineered for deployment in the SIEM:

```yaml
title: Data Exfiltration via Pastebin API in PowerShell
id: c92f0598-5678-4a5e-994d-70580c5e9f08
status: experimental
description: Detects PowerShell scripts utilizing the Pastebin API endpoint (api_post.php) to upload data.
author: SOC Analyst Portfolio
logsource:
  product: windows
  service: powershell
detection:
  selection:
    EventID: 4104
    ScriptBlockText|contains:
      - 'pastebin.com/api/api_post.php'
      - 'api_dev_key'
      - 'api_paste_code'
  condition: selection
falsepositives:
  - Legitimate developer scripts testing Pastebin API integrations
level: high
tags:
  - attack.t1567.002
  - attack.t1059.001
```

## 🚀 Decision Tree 
1. **Analyze Initial Vector:** Did the user execute a script downloaded from an external link or email?
   - If Yes -> Proceed to PowerShell Script Block logs (Event ID 4104).
2. **Evaluate Script Intent:** Does the PowerShell script gather system info (`whoami /all`) and write it to disk?
   - *Confirmed staging of `sys_usrs.txt`.*
3. **Check Exfiltration Mechanisms:** Does the script invoke `Invoke-RestMethod` or `Invoke-WebRequest` targeting known developer sharing sites (`pastebin.com`, `ghostbin.co`, `hastebin.com`)?
   - If Yes -> **Verdict: True Positive - Successful Data Leakage.**
4. **Action:** Isolate host immediately, purge phishing email, and flag the generated Pastebin URL for takedown.

## 📝 Playbook Questions & Answers
- **Should the device be isolated?**
  - *Answer:* Yes.
  - *Reasoning:* An email from `info@dachfix.com` contained a link to a malicious script which was downloaded and executed, resulting in unauthorized discovery (`whoami /all`) and data exfiltration to Pastebin.
- **Determine the Scope:**
  - *Answer:* No (Localized to one machine).
  - *Reasoning:* Searching the sender address in Email Security confirmed the email was only received by `gabriela@letsdefend.io`.
- **IP Reputation Check:**
  - *Answer:* Yes.
  - *Reasoning:* The payload was downloaded from an AWS S3 URL flagged as malicious across threat intelligence platforms.
- **Attacker IP Analysis:**
  - *Answer:* External.
  - *Reasoning:* The script was delivered via an external phishing vector (`dachfix.com`) and exfiltrated data to an external web service (`pastebin.com`).
- **Determine the Type of Discovery:**
  - *Answer:* System Owner/User Discovery (T1033).
  - *Reasoning:* The command `whoami.exe /all` was executed by the script to enumerate user accounts, SIDs, privileges, and group memberships.
- **Determine the OS (Operating System):**
  - *Answer:* Windows (Windows 10).
  - *Reasoning:* Endpoint Security confirmed the host operating system is Windows 10.

## Response & Containment Actions Taken
- **Host Isolation:** The compromised endpoint (`Gabriela / 172.16.17.63`) was immediately **Isolated** from the network via EDR to prevent any further data harvesting or secondary payload execution.
- **Perimeter Blocking:** The phishing sender domain (`dachfix.com`) was added to the perimeter blocklist.
- **Email Purge:** The phishing email was purged globally from the Exchange server.
- **Why:** Isolating the host stops active data leakage channels and prevents the attacker from utilizing the compromised workstation for lateral movement.

## Recommendations
1. **Pastebin / Code-Sharing Egress Filtering:** Implement strict web proxy controls that inspect outbound HTTPS traffic to code-sharing sites (`pastebin.com`, `gist.github.com`) from non-developer workstations to prevent unauthorized data exfiltration.
2. **PowerShell Script Block Logging:** Ensure Event ID 4104 is actively forwarded to the SIEM. Script block logging is the only way to inspect the internal variables and API endpoints of obfuscated `.ps1` scripts.
3. **Privileged Account Review:** Because the script successfully executed `whoami /all`, review active directory logs to ensure no administrator credentials or sensitive SIDs were leveraged by the attacker following the leak.
