

# SOC275 - Application Token Steal Attempt Detected 

## Alert Overview
- **Severity:** High
- **Detection Source:** WAF / SIEM Proxy Logs
- **Asset Affected:** Gloriana (172.16.17.172)
- **Threat Type:** Phishing / Host Header Injection / Token Theft
- **Status:** True Positive (Compromised)

## Strategy and Technical Context
This incident highlights a sophisticated intersection of Social Engineering and Web Application Exploitation, specifically **Host Header Injection**. The threat actor's strategy is to exploit a misconfigured reverse proxy or load balancer on a target application. 

Instead of building a fake website from scratch, the attacker sends a legitimate password reset request to the target application but injects their own malicious domain (`homespottersf.com`) into the `X-Forwarded-Host` HTTP header. The vulnerable application dynamically generates the password reset email using this poisoned header. When the victim clicks the link in their email, they are directed to the attacker's server, which then transparently proxies the traffic. This allows the attacker to intercept and steal the highly sensitive password reset token in cleartext.

## Investigation Steps

### 1. Alert Triage and Network Log Correlation
The alert identified a suspicious GET request indicating an application token steal attempt.
- **Trigger Request:** `GET /reset-password?email=gloriana@letesdefend.io HTTP/1.1`
- **Initial Log Review:** The raw proxy log for this request revealed an HTTP `302 Redirect` to the target URL: `http://homespottersf.com:8081/reset-password`. Crucially, the `X-Forwarded-Host` header was manipulated to point to `homespottersf.com`.

### 2. Token Theft Verification
To determine the impact of this redirection, further proxy logs associated with the malicious domain were reviewed.
- **Finding:** A subsequent log at 08:23:46 showed a POST request to the attacker's server:
  `POST /reset-password?token=123letsdefendisthebest123 HTTP/1.1`
- **Analysis:** This confirms the attack was successful. The victim's application token (`123letsdefendisthebest123`) was transmitted in cleartext via the URL parameter directly to the attacker-controlled server (`X-Forwarded-Host: homespottersf.com`). 

### 3. Initial Access Vector (Email Analysis)
To understand how the user was coerced into initiating this request, the Email Security gateway was queried for the affected user (`gloriana@letsdefend.io`).
- **Sender:** `noreply@discordglobal.com` (Spoofed / Typosquatted Domain)
- **Subject:** `Password Expired - Reset Your Password`
- **Lure:** A classic credential harvesting lure masquerading as a Discord security alert.
- **Finding:** The "Reset Password" button in the email contained the poisoned link generated by the Host Header Injection.

### 4. Threat Intelligence Enrichment
The malicious domain (`homespottersf.com`) and its resolving IP address (`23.82.12.29`) were queried against Threat Intelligence platforms.
- **VirusTotal:** The domain was flagged by multiple vendors specifically for Phishing.
- **AbuseIPDB:** The IP was associated with malicious activity, confirming the hostile nature of the redirect infrastructure.

## Analysis & Findings
The incident is a confirmed **True Positive (Successful)**. The user "Gloriana" fell victim to a phishing email containing a poisoned password reset link. The attacker successfully utilized Host Header Injection (`X-Forwarded-Host`) to force the application to route the password reset token to a malicious proxy (`homespottersf.com`). Because the proxy log explicitly captured the token being sent to the attacker's server, the user's application account is considered fully compromised.

## Blind Spots
- **Application Scope:** While the email lure purported to be from Discord, the specific internal application that generated the `123letsdefendisthebest123` token is not explicitly identified in the proxy logs. Application-specific audit logs are required to determine exactly which service the token grants access to.

## False Positives: Legitimate Activity Comparison
- **Legitimate Password Resets:** Users frequently reset passwords. A standard reset will show a `302 Redirect` back to the *authorized* application domain. The presence of an unrecognized, external domain in the `X-Forwarded-Host` or `Target URL` field is the definitive differentiator between a benign reset and an attack.

## Decision Tree for Token Theft / Header Injection
1. **Analyze Trigger Request:** Is the request associated with an authentication or password reset endpoint?
   - If Yes -> Check the HTTP Headers.
2. **Examine Headers:** Does the `Host` or `X-Forwarded-Host` header match the legitimate corporate domain?
   - If No (Points to external/unknown domain) -> High probability of Host Header Injection.
3. **Check Traffic Logs:** Was a subsequent request made containing a `token=` or `session=` parameter to the external domain?
   - If Yes -> Verdict: **True Positive - Successful Compromise (Token Stolen).**
4. **Action:** Revoke the token, isolate the host, and initiate an incident response.

## Response & Closure
- **Action Taken:** The host (`Gloriana / 172.16.17.172`) was **Contained** via the Endpoint Security console to halt further interaction with the attacker's proxy. The phishing email was purged from the environment.
- **Containment Required:** Yes.
- **Closure Reason:** True Positive. Application token successfully stolen via Host Header Injection and phishing.

## Recommendations
1. **Application Remediation (Crucial):** The web application developers must remediate the Host Header Injection vulnerability. The application must either strictly validate the `Host` and `X-Forwarded-Host` headers against a hardcoded whitelist of approved domains or rely on server-side variables (rather than client-supplied HTTP headers) to generate password reset links.
2. **Token Revocation:** Immediately invalidate the stolen token (`123letsdefendisthebest123`) and force a password reset and active-session termination for the affected user.
3. **Phishing Awareness Training:** Assign the user to targeted phishing simulation training, focusing on verifying URL destinations before clicking links in security-related emails.
